# 并发内存池

## 项目概述

基于 **TCMalloc** 思想实现的高性能并发内存池，采用三层缓存架构（ThreadCache → CentralCache → PageCache），解决多线程环境下内存分配的性能瓶颈问题。

## 核心架构

```
ThreadCache (线程私有，208个FreeList)
       ↓ 批量获取/释放
CentralCache (全局唯一，按大小分段加锁)
       ↓ 按页申请/合并
PageCache (全局唯一，管理物理页)
       ↓
    操作系统 (VirtualAlloc/mmap)
```

## 核心技术点

| 技术 | 说明 |
|------|------|
| **TLS线程本地存储** | 每个线程独立缓存，线程内分配无需加锁 |
| **三级缓存架构** | 减少锁竞争，按需批量调度 |
| **内存对齐策略** | 8~8192字节多级对齐，减少碎片 |
| **Span管理** | 通过PageToSpan映射支持跨线程释放 |
| **对象池** | ObjectPool预分配Span对象，避免频繁new/delete |

## 内存管理策略

- **ThreadCache**：管理线程私有的自由链表，按大小分类
- **CentralCache**：管理多个Span，提供批量获取/释放
- **PageCache**：管理物理页映射，负责与系统交互
- **SizeClass**：规范化内存大小（1B~256KB分208个规格）

## 设计亮点

1. **高效并发**：ThreadCache无锁访问，只有跨缓存时才加锁
2. **批量调度**：减少系统调用次数，每次批量获取多个对象
3. **智能回收**：FreeList过长时自动归还CentralCache
4. **跨线程释放**：通过地址映射找到Span，无需关心分配线程

## 技术栈

- C++11 / Windows API / Linux API
- 互斥锁 / TLS线程本地存储
- 单例模式 / 对象池模式
